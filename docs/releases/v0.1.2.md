# codex-keysmith v0.1.2

## 简体中文

v0.1.2 修复外部工具重写 `config.toml` 后，schema-1 manifest 将整份配置误判为所有权冲突的问题，并纳入 v0.1.1 之后完成的 Release 恢复流程加固。现有已签名 tag、既有 Release 资产与校验和保持为不可变历史记录。

### CCSwitch / 外部配置工具兼容性

v0.1.1 虽然只修改顶层 `model_instructions_file`，但部署 manifest 长期使用整份 `config.toml` 的 `size`、`mtime_ns` 和 SHA-256 判断所有权。CCSwitch 等工具修改 model、provider 或其他无关字段，甚至只重新保存相同字节并改变 mtime，都可能让 `--status` 和 `--uninstall` 报告 `config.toml 已漂移`。

v0.1.2 将 config 的长期所有权收窄为顶层 `model_instructions_file` 的语义所有权：

- 只要该字段仍引用当前 manifest 管理的 Markdown，CCSwitch 对其他字段的重写不会阻塞 status 或卸载；
- 卸载只恢复或移除部署前的 `model_instructions_file` 语句，并保留其他 live config 内容；
- 当前字段缺失、改指其他文件、存在歧义或使用扫描器无法安全定位的结构时，仍会 fail closed；
- 整文件指纹继续用于操作期间的稳定读取、CAS、durable snapshot、回滚、并发拒绝和崩溃恢复；
- v0.1.0 / v0.1.1 的 schema-1 manifest 无需手工编辑即可使用新语义。

### Release 与文档

- Release 恢复现在保留既有不可变签名 tag，要求所有阻断任务在其精确 peeled commit 上重新执行，并通过 numeric Release ID 与 GitHub 返回的 upload URL 暂存 draft 资产。
- README 已拆分为简洁的中英文 quick start、完整 reference 和智能体安装提示，同时保留事务、安全、Windows beta 与系列项目链接。
- Windows fresh deployment 继续按 `EXPLICIT_BETA` 开放；deploy preview 与执行显示 beta 警告，status、recover、uninstall 与 restore-hooks 不误报部署警告。该策略仍不构成正式 Windows 支持承诺。

### 升级与校验

无需先卸载 v0.1.1。下载并校验 v0.1.2 独立脚本后，可直接对现有部署运行 `--status` 或 `--uninstall`；脚本版本升级本身不会改写用户配置。

```bash
sha256sum --check SHA256SUMS
python3 codex-instruct-v0.1.2.py --version
python3 codex-instruct-v0.1.2.py --codex-dir ~/.codex --status --lang zh-CN
```

Windows PowerShell 可使用：

```powershell
py -3.12 .\codex-instruct-v0.1.2.py --version
py -3.12 .\codex-instruct-v0.1.2.py --codex-dir "$env:USERPROFILE\.codex" --status --lang zh-CN
```

如果 status 报告 durable journal，请先预览 `--recover`，确认后再添加 `--yes`；不要手工删除或编辑 journal、marker、snapshot、manifest 或备份。

## English

v0.1.2 fixes schema-1 manifest ownership conflicts after an external tool rewrites `config.toml`, and includes the release-recovery hardening completed after v0.1.1. Existing signed tags, published Release assets, and checksums remain immutable historical artifacts.

### CCSwitch / external configuration compatibility

Although v0.1.1 edited only the top-level `model_instructions_file`, its deployment manifest treated the complete `config.toml` `size`, `mtime_ns`, and SHA-256 as long-lived ownership. CCSwitch or another tool could therefore change model, provider, or unrelated fields—or merely resave identical bytes with a new mtime—and cause `--status` or `--uninstall` to report config drift.

v0.1.2 narrows long-lived config ownership to the semantic value of the top-level `model_instructions_file`:

- CCSwitch rewrites of unrelated fields no longer block status or uninstall while the field still references the manifest-owned Markdown;
- uninstall restores or removes only the pre-deployment `model_instructions_file` statement and preserves every other live config field;
- a missing field, a different target, target-field ambiguity, or a statement structure the conservative scanner cannot locate safely still fails closed;
- complete-file fingerprints remain in force for operation-time stable reads, CAS, durable snapshots, rollback, concurrency rejection, and crash recovery;
- existing v0.1.0 / v0.1.1 schema-1 manifests work under the new interpretation without manual edits.

### Release and documentation

- Release recovery now preserves an existing immutable signed tag, reruns every blocking job against its exact peeled commit, and stages draft assets through the numeric Release ID and GitHub-returned upload URL.
- The README is split into concise Chinese and English quick starts, a complete reference, and an agent-install prompt while preserving transaction, security, Windows beta, and sibling-project links.
- Windows fresh deployment remains available under `EXPLICIT_BETA`; deploy preview and execution show a beta warning, while status, recover, uninstall, and restore-hooks do not emit that deployment warning. This is still not a formal Windows support commitment.

### Upgrade and verification

You do not need to uninstall v0.1.1 first. After downloading and verifying the v0.1.2 standalone script, run it directly against an existing deployment with `--status` or `--uninstall`; changing script versions alone does not edit user configuration.

```bash
sha256sum --check SHA256SUMS
python3 codex-instruct-v0.1.2.py --version
python3 codex-instruct-v0.1.2.py --codex-dir ~/.codex --status --lang en
```

On Windows PowerShell:

```powershell
py -3.12 .\codex-instruct-v0.1.2.py --version
py -3.12 .\codex-instruct-v0.1.2.py --codex-dir "$env:USERPROFILE\.codex" --status --lang en
```

If status reports a durable journal, preview `--recover` first and add `--yes` only after review. Do not manually delete or edit journals, markers, snapshots, manifests, or backups.
