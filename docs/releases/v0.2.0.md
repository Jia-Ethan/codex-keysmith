# codex-keysmith v0.2.0

<!-- WINDOWS_FRESH_DEPLOYMENT_POLICY: EXPLICIT_BETA -->

## 简体中文

v0.2.0 将桌面客户端源码并入 canonical 仓库，并保持 Python CLI 是部署、恢复和卸载事务的唯一实现。

- 新增 `gui/` 桌面客户端源码，使用 Tauri 2 + React，覆盖状态查看、强制预览门禁、部署、卸载、hooks 恢复、中断恢复、设置和中英双语界面。
- CLI 与 GUI 源码统一为 `0.2.0`。manifest 与 journal schema 仍为 1，已有 v0.1.0-v0.1.3 部署无需迁移。
- 桌面端启动时会等待当前 CLI 定位完成，不再在内置 CLI 或手动路径仍在验证时误报“未找到 CLI”。
- Windows 自动状态发现会忽略仅含缓存的 `%LOCALAPPDATA%\OpenAI\Codex` 目录，同时继续报告真实配置、受管文件、异常受管节点、事务残留和 cleanup marker；显式 `--codex-dir` 行为不变。
- CLI 以非零状态返回语义完整报告时，桌面端会保留目录卡片、退出码、stderr 和完整 stdout；截断、字段不全、超时或终止句与退出码不一致的报告继续失败关闭。
- 桌面端不提供托盘驻留：所有 Keysmith 后端调用都受生命周期租约保护，关闭请求先建立退出屏障，并在活动调用完成后自动退出。应用仅允许单实例；重复启动会恢复并显示现有窗口，同时请求系统聚焦。
- Windows 原生候选门禁会隔离用户配置目录与 Codex Desktop 运行目录，验证活动 sidecar 期间排队关闭、二次启动交接、原生空闲关闭，以及最终无 GUI/sidecar 残留。
- 设置页显示桌面版本、`candidate` / `development` 构建类型和完整 source commit；候选验证要求 production JavaScript bundle 内嵌与 build manifest 完全一致的 commit。
- PyInstaller frozen 模式生成 hooks 恢复命令时直接调用打包后的可执行文件，不再追加临时解包目录中的 Python 源文件路径；源码模式仍输出 `python + codex-instruct.py`。
- 正式打包流程会原生构建 PyInstaller CLI sidecar 并放入应用包，最终用户无需单独安装 Python；开发模式和高级手动配置仍可回退到外部 `codex-instruct.py`。
- `desktop-v0.2.0-beta.5` 统一公开 macOS Apple Silicon unsigned DMG、Windows x64 unsigned NSIS、单文件 CLI、确定性源码归档和完整 `SHA256SUMS`；两个平台 candidate ZIP 保留各自的 build manifest 与内部校验值。
- macOS DMG 未进行 Apple 签名或公证，Windows 安装器未进行 Authenticode 签名；两者均为 `Beta / unsigned / native-CI-validated`，没有实体设备验收。底层 Windows CLI fresh deployment 仍为 `EXPLICIT_BETA`，不构成正式支持承诺。

桌面客户端源码入口：<https://github.com/Jia-Ethan/codex-keysmith/tree/main/gui>

推荐升级前后各运行一次：

```bash
python3 codex-instruct-v0.2.0.py --version
python3 codex-instruct-v0.2.0.py --codex-dir ~/.codex --status --lang zh-CN
```

## English

v0.2.0 brings the desktop client source into the canonical repository while keeping the Python CLI as the sole implementation of deployment, recovery, and uninstall transactions.

- Adds the `gui/` desktop client source using Tauri 2 + React, with status, mandatory preview gates, deployment, uninstall, hooks restore, interrupted-operation recovery, settings, and bilingual UI flows.
- Unifies the CLI and GUI source version at `0.2.0`. Manifest and journal schemas remain at 1, so deployments created by v0.1.0-v0.1.3 require no migration.
- Desktop startup now waits for the active CLI resolution to finish instead of reporting that the CLI is missing while the bundled sidecar or a manual path is still being validated.
- Automatic Windows status discovery ignores a cache-only `%LOCALAPPDATA%\OpenAI\Codex` directory while preserving real configuration, managed files, abnormal managed nodes, transaction residue, and cleanup markers. Explicit `--codex-dir` behavior is unchanged.
- When the CLI returns a semantically complete non-zero status report, Desktop preserves the directory cards, exit code, stderr, and full stdout. Truncated, field-incomplete, timed-out, or exit-inconsistent reports still fail closed.
- Desktop has no tray-resident mode: lifecycle leases cover every Keysmith backend call, close requests establish an exit barrier, and the application exits automatically after active calls finish. Only one GUI instance is allowed; a repeated launch restores and shows the existing window while requesting system focus.
- The native Windows candidate gate separates the user configuration directory from the Codex Desktop runtime directory, exercises queued close during an active sidecar, verifies second-instance handoff and native idle close, and checks that no GUI or sidecar process remains.
- Settings displays the desktop version, `candidate` / `development` build channel, and full source commit. Candidate validation requires the production JavaScript bundle to embed the exact commit recorded in the build manifest.
- PyInstaller-frozen builds now generate hooks-restore commands that invoke the packaged executable directly instead of appending a Python source path inside the temporary extraction directory. Source mode continues to emit `python + codex-instruct.py`.
- Packaged builds create a native PyInstaller CLI sidecar and include it in the application bundle, so end users do not need a separate Python installation. Development mode and advanced manual configuration retain the external `codex-instruct.py` fallback.
- `desktop-v0.2.0-beta.5` publishes the Apple Silicon macOS unsigned DMG, Windows x64 unsigned NSIS installer, standalone CLI, deterministic source archives, and complete `SHA256SUMS` together; both platform candidate ZIPs retain their build manifests and internal checksums.
- The DMG has no Apple signature or notarization, and the Windows installer has no Authenticode signature. Both remain `Beta / unsigned / native-CI-validated` without physical-device acceptance. Windows CLI fresh deployment remains `EXPLICIT_BETA`, not a formal support commitment.

Desktop client source: <https://github.com/Jia-Ethan/codex-keysmith/tree/main/gui>

Recommended checks before and after upgrading:

```bash
python3 codex-instruct-v0.2.0.py --version
python3 codex-instruct-v0.2.0.py --codex-dir ~/.codex --status --lang en
```
