# codex-keysmith v0.1.3

## 简体中文

v0.1.3 将 Issue #9 中观察到的 CCSwitch 配置切换行为收敛为明确的只读状态契约。

- `--status` 现在区分 `active`、`inactive-by-config`、`conflict` 和 `not-installed`。
- 当 Keysmith 的 manifest、提示词和恢复证据完整，但当前有效 `config.toml` 不含顶层 `model_instructions_file` 时，状态显示为 `inactive-by-config`，不再误报结构损坏。
- `inactive-by-config` 只放宽只读状态解释；deploy 和 uninstall 仍保持 blocked，必须先切回引用受管 Markdown 的 active 配置。
- 提示词、manifest 或必要备份缺失、异常、漂移时仍显示 `conflict`；异常 manifest 的中英文诊断和 uninstall 输出已修正。
- 文档新增 CCSwitch On/Off 双 Provider 流程，并说明通用配置片段可能重新注入字段、普通切换 backfill 需要验证、代理接管不属于稳定兼容契约、hooks 不随 Provider 配置切换，以及配置只对新会话生效。
- Release bundle 现在包含英文 README、完整 reference、智能体安装文档和 README 预览图，离线相对链接由测试验证。

升级无需迁移：manifest 与 journal schema 仍为 1，v0.1.0-v0.1.2 的现有部署可直接使用 v0.1.3 脚本执行 `--status`、deploy、recover 或 uninstall。Windows fresh deployment 仍为 beta。

推荐升级前后各运行一次：

```bash
python3 codex-instruct-v0.1.3.py --version
python3 codex-instruct-v0.1.3.py --codex-dir ~/.codex --status --lang zh-CN
```

## English

v0.1.3 turns the CCSwitch configuration behavior observed in Issue #9 into an explicit read-only activation-state contract.

- `--status` now distinguishes `active`, `inactive-by-config`, `conflict`, and `not-installed`.
- When the Keysmith manifest, prompt, and recovery evidence are healthy but the effective `config.toml` has no top-level `model_instructions_file`, status reports `inactive-by-config` instead of structural damage.
- `inactive-by-config` changes read-only interpretation only. Deploy and uninstall remain blocked until an active config restores the managed Markdown reference.
- Missing, abnormal, or drifted prompt, manifest, or required backup evidence remains a `conflict`; localized diagnostics and invalid-manifest uninstall reporting are corrected.
- Documentation now covers the CCSwitch two-provider On/Off workflow, Common Config reinjection, backfill verification, the proxy-takeover compatibility boundary, directory-global hook isolation, and the new-session-only effect.
- Release bundles now include the English README, full reference, agent-install guide, and README preview image, with local relative links validated by tests.

No migration is required: manifest and journal schemas remain at 1, and deployments created by v0.1.0-v0.1.2 can be managed directly with the v0.1.3 script. Windows fresh deployment remains beta.

Recommended checks before and after upgrading:

```bash
python3 codex-instruct-v0.1.3.py --version
python3 codex-instruct-v0.1.3.py --codex-dir ~/.codex --status --lang en
```
